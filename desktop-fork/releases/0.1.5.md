# OpenCodex Desktop 0.1.5

## 中文

- 完整同步上游稳定版 **OpenCodex 2.73.0**（上一版本基于 2.63.0），带入此期间的提供方、模型目录、代理及管理面板更新。
- 包含上游 **GPT-6.1 Sol** 模型目录支持，以及 DeepSeek 等提供方的兼容性更新。
- 保留本 fork 的独立桌面壳：关闭窗口驻留托盘、停止并恢复原生 Codex、仅恢复原生、重新接回代理，以及持久配置与固定端口。
- 适配上游新的退出清理和桌面界面逻辑；本客户端仍通过自己的桌面控制页管理生命周期及升级，不调用上游桌面壳的更新器或窗口接口。
- 内置运行时升级至 **2.73.0**，Bun 维持 **1.4.0**。应用身份与用户数据目录不变，已有提供方配置无需重新填写。
- 升级前从旧版托盘选择“退出应用并恢复原生 Codex”，保留应用数据，再安装新版。
- Windows、Apple Silicon Mac 和 Intel Mac 安装包从同一提交构建并校验后发布。macOS 安装包继续使用 ad-hoc 签名，未作 Apple 公证。

本地验证：核心与桌面 TypeScript 检查、228 项模型/路由/管理安全/结构回归、33 项桌面测试、8 项 Rust 测试、67 项 GUI 测试、GUI 构建与国际化检查、结构检查及隐私扫描通过。隔离的完整启停测试与打包运行时测试通过，真实用户配置保持不变。上游已有数万项测试，本次按 fork 合并边界执行针对性验证，未运行完整上游套件或发送真实付费模型请求；三平台构建及安装包验证由发布流水线执行。

发布边界复核：保留上游账户切换能力校验与本 fork 的管理操作限制；生产依赖版本和本 fork 发布工作流未改变。发布仍只允许匹配桌面版本的标签，经三个平台产物版本、提交及校验和核验后执行，不增加工作流权限或暴露凭据。

## English

- Merge upstream stable **OpenCodex 2.73.0**, upgrading the proxy, provider integrations, model catalog and dashboard from the previous 2.63.0 baseline.
- Include upstream **GPT-6.1 Sol** catalog support and provider compatibility updates, including DeepSeek.
- Retain this fork's close-to-tray shell, native Codex stop/restore/reconnect actions, persistent configuration and saved proxy port.
- Integrate upstream teardown changes while preserving the fork's restore ownership checks. Fork update controls remain separate from upstream desktop updater and window APIs.
- Bundle runtime **2.73.0** with **Bun 1.4.0**. Application identity and user data paths remain unchanged.
- Exit the previous version from its tray with native Codex restoration, retain application data, then install this version.
- Windows and both macOS architectures are built from the same commit and verified before publishing. macOS packages remain ad-hoc signed and are not notarized by Apple.

Local validation passed: root/desktop typechecks; 228 model, routing, management-security and structure tests; 33 desktop tests; 8 Rust tests; 67 GUI tests; GUI build/i18n; structure and privacy checks; isolated persistent-lifecycle and relocated packaged-runtime smoke tests. Real user configuration was unchanged. Given the upstream suite's size, validation targeted the fork integration boundaries rather than running the full upstream suite. No paid model requests were made; the release workflow builds and verifies all three platforms.

Security review of the integration preserves account-switch capability validation and fork lifecycle restrictions. Production dependency versions and the fork release workflow are unchanged. Publication remains tag-gated and requires matching platform artifacts, versions, commit and checksums, without expanded workflow permissions or credential exposure.
