# OpenCodex Desktop 0.1.6

## 中文

- 完整同步上游稳定版 **OpenCodex 2.80.0**，从 2.73.0 升级，带入期间的提供方兼容性、模型目录、代理可靠性、依赖和管理面板更新。
- 保留本 fork 的独立桌面壳：关闭窗口驻留托盘、停止并恢复原生 Codex、仅恢复原生、重新接回代理、持久配置与固定端口。
- 合并上游新的管理面板功能及翻译，同时保留本 fork 的桌面控制入口；上游专用窗口和缩放接口只在其桌面壳中启用。
- 内置运行时 **2.80.0**，Bun 维持上游固定的 **1.4.0**。应用身份和用户数据目录不变，已有提供方配置无需重新填写。
- 升级前从旧版托盘选择“退出应用并恢复原生 Codex”，保留应用数据，再安装新版。
- Windows、Apple Silicon Mac 和 Intel Mac 安装包从同一提交构建并核验后发布。macOS 包继续使用 ad-hoc 签名，未作 Apple 公证。

本地验证：核心与桌面 TypeScript 检查、255 项模型/路由/管理安全/结构回归、33 项桌面测试、8 项 Rust 测试、96 项 GUI 测试、GUI 构建与国际化检查、结构检查和隐私扫描通过。根目录及 GUI 依赖安全检查未发现漏洞。隔离启停及打包运行时测试通过，真实用户配置保持不变。鉴于上游测试套件规模，本次按 fork 合并边界执行针对性回归，未运行完整上游套件或发送真实付费模型请求；三平台安装包由发布流水线构建和验证。

发布边界复核：保留上游管理校验和本 fork 生命周期限制，依赖版本沿用上游锁文件；本 fork 发布工作流及权限保持不变。发布仍要求匹配桌面版本的标签、同一提交的三平台产物及校验和验证。

## English

- Merge upstream stable **OpenCodex 2.80.0**, upgrading from 2.73.0 with provider compatibility, model catalog, proxy reliability, dependency and dashboard updates.
- Retain this fork's close-to-tray shell, native Codex stop/restore/reconnect actions, persistent configuration and saved proxy port.
- Merge dashboard features and translations while retaining fork desktop controls. Upstream-only window and zoom APIs remain scoped to upstream's own shell.
- Bundle runtime **2.80.0** with upstream-pinned **Bun 1.4.0**. Application identity and user data paths remain unchanged.
- Exit the previous version from its tray with native Codex restoration, retain application data, then install this version.
- Windows and both macOS architectures are built from the same commit and verified before publication. macOS bundles remain ad-hoc signed and are not notarized by Apple.

Local validation passed: root/desktop typechecks; 255 model, routing, management-security and structure tests; 33 desktop tests; 8 Rust tests; 96 GUI tests; GUI build/i18n; structure and privacy checks; isolated persistent-lifecycle and relocated packaged-runtime smoke tests. Root and GUI dependency audits reported no vulnerabilities. Real user configuration was unchanged. Validation targeted the fork integration boundaries rather than the full upstream suite; no paid model requests were made. The release workflow builds and verifies all three platforms.

Security review of the integration preserves upstream management validation and fork lifecycle restrictions. Dependencies follow upstream lockfiles. Fork release workflow permissions remain unchanged, and publication still requires the matching version tag and verified artifacts and checksums from the same commit.
