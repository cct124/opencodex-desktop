# M3：桌面适配与 Windows 安装包

日期：2026-09-11。基线：`b72497712`。工作分支：`codex/desktop-m3-distribution`。
当前为本地开发安装包，未签名、未发布；M3 保持开放，尚未完成干净 Windows 和完整手工验收。

## 本轮实现

- 保留完整上游管理页面和代理实现。桌面提示及停止、重启、服务、独立托盘、更新、重启 Codex 等入口转到本地桌面控制页；新增提示覆盖全部九种 GUI 语言。
- 托盘负责应用生命周期；暂不安装另一套全局服务或开机启动。Codex 本身由用户完成当前轮次后手动重启。
- WebView2 导出文件保存到用户下载目录的 `OpenCodex Desktop/` 子目录，增加唯一文件名前缀；控制页提供下载目录和 Releases 页面入口。
- release 从安装目录的 `runtime/` 加载固定 Bun、后端、生产依赖和 GUI，启动时检查必要资源及匹配版本。debug 继续从源码启动；预览和测试参数仅对 debug 有效。
- 新增固定版本的 Tauri CLI、资源暂存脚本、资源校验清单、依赖许可文件和 NSIS 构建入口。构建清单用于检查完整性，不代表数字签名。
- NSIS 仅安装到当前用户，携带 WebView2 引导程序，缺少 WebView2 时仍需联网。升级使用完整安装包，禁止降级；安装或卸载前必须从托盘退出。默认卸载保留应用数据，交互式卸载可明确选择删除数据。

## 安装包与复现

从仓库根目录执行：

```powershell
& .\node_modules\bun\bin\bun.exe install --cwd desktop --frozen-lockfile
cargo fetch --locked --manifest-path desktop/src-tauri/Cargo.toml
& .\node_modules\bun\bin\bun.exe run desktop/scripts/build-installer.ts
& .\node_modules\bun\bin\bun.exe run desktop/scripts/package-smoke.ts
```

产物：`desktop/src-tauri/target/release/bundle/nsis/OpenCodex Desktop_2.50.0_x64-setup.exe`。
大小：52,925,812 字节（约 50.5 MiB）。同目录有 `.sha256` 校验文件。

资源清单覆盖 5,780 个文件，另有清单本身。

## 上游回归对照

当前 Codex Windows 宿主会将部分已知目录重定向到应用包的 LocalCache。
上游有效用户协调器拒绝该路径身份差异，影响连接写入、恢复和多项测试。
保留原有路径检查，没有为本机测试放宽产品约束。

测试包装器默认也无法获取该协调器锁，因此本轮使用仓库已有的
`OCX_TEST_NO_QUEUE=1`。该选项关闭测试排队锁，测试 HOME 和真实配置写入保护仍保留。

- `bun run test` 在 903 秒达到仓库全量并行阶段的时限，退出 124；当时输出包含 283 个失败。
- 补跑 318 个尚未完成或位于终止窗口的文件：5,829 项通过、44 项跳过、178 项失败、8 个错误。两轮合计到达 1,163 个测试文件；这不等同于一次完整的绿色全量运行。
- 在独立 worktree 的未修改 `b72497712` 基线中，对所有失败文件进行了对照。461 个失败用例中，432 个在基线复现。
- 其余 29 个在当前代码的定向复查中通过：9 个在通常并行设置下通过；20 个在 `--parallel=1 --timeout 30000` 下通过。超时后共享测试状态的错误也出现在原始日志中；原始失败记录仍保留。
- 全量门禁保持失败，不能用定向复查替代正式 PR / 发布所需的默认全量绿色结果。

日志与对照 JSON 位于 gitignored 的 `.tmp/m3-*.log`、`.tmp/m3-test-comparison.json`。
基线位于 `.worktrees/m3-baseline`。测试结果不含需要写入公开笔记的凭据。

## 尚未完成的验收

- 本宿主中的 Codex 接回受协调器路径检查阻止；原生生命周期测试在该步骤失败。启动中停止也返回清理失败，未修改基线的直接启动/停止复现了同一结果。不能宣称本机完整生命周期通过。
- 当前机器没有可用 Windows Sandbox，尚未在完全没有开发工具的新 Windows 用户/虚拟机完成安装、WebView2 首次安装、升级和卸载验收。系统 PATH 隔离测试只证明内置运行时能独立工作。
- 原生自动化入口验证了实际窗口行为，本轮没有完整的鼠标/键盘手工页面验收、关机/注销验收或新的交互式 OAuth 登录。用户本轮选择的范围是使用已有登录发一次最小请求。
- 发布前仍需默认全量绿色结果、维护者审查和正式签名/发布流程。
