# M1：独立窗口与项目后端

日期：2026-09-11。平台：Windows x64。

## 实现

`desktop/src-tauri/` 增加 Tauri 2.11.2 工程，提交 Cargo 锁文件。Rust 层管理窗口和一个明确属于自身的 Bun 子进程。上游 favicon 直接复用，构建时包装为 Windows 图标，未修改像素或增加一套品牌资源。

`desktop/runtime/entry.ts` 在新建的 `.tmp/desktop/session-*` 中准备开发环境，然后导入原有 `src/cli/index.ts` 执行启动流程。程序始终使用项目内 Bun，原有管理界面来自 `gui/dist/`，没有调用全局 `ocx`。此阶段尚未将完整资源目录封装进安装包。

启动检查同时核实本次子进程 PID、实际端口、上游 HMAC 身份证明和 `/readyz`。任意端口上的普通 HTTP 200 不会被视为成功。后端就绪后创建管理窗口，WebView2 完成页面加载后才隐藏启动提示页。

Rust 通过子进程 stdin 请求关闭，Bun 在进程内部触发上游已注册的 SIGINT 清理处理器。这样 Windows 下也能进入排空和配置恢复流程。通信管道结束时同样请求关闭；保留有界的超时退出，且只操作自己持有的子进程。

## 与现有安装共存

开发环境隔离 HOME、USERPROFILE、OpenCodex、Codex、Claude、AppData 和临时目录，清除继承的提供方凭据、代理路由和后台服务身份变量。启动时客户端集成默认关闭，并启用上游开发环境写入保护。

由于 Windows 服务、托盘启动项等系统状态不能仅靠更换目录隔离，增加了一个仅在 `OPENCODEX_DESKTOP_PREVIEW=1` 下生效的管理接口判断，阻止全局安装、更新、重启和集成归属切换。正常上游 CLI / 代理行为不变。提供方编辑和常规查询保留。

宿主只注册启动状态和退出两个命令，命令验证调用窗口标签；权限配置不向远程管理页面开放。外部 HTTP / HTTPS 导航交给系统浏览器，其他外部导航被拒绝。

## 复现

在仓库根目录，项目内 Bun 已安装并完成上游 GUI 构建：

```powershell
& .\node_modules\bun\bin\bun.exe x tsc --noEmit
& .\node_modules\bun\bin\bun.exe x tsc --project desktop/tsconfig.json
& .\node_modules\bun\bin\bun.exe test tests/server/management-desktop-preview.test.ts tests/test-layout.test.ts tests/test-layout-tooling.test.ts
& "$env:USERPROFILE/.cargo/bin/cargo.exe" test --offline --locked --manifest-path desktop/src-tauri/Cargo.toml
```

桌面独立测试在 `desktop/` 中执行，使用该目录的 Bun 测试配置：

```powershell
& ..\node_modules\bun\bin\bun.exe test tests/runtime.test.ts
& ..\node_modules\bun\bin\bun.exe run scripts/smoke.ts
& ..\node_modules\bun\bin\bun.exe run scripts/smoke.ts --parent-eof
```
