# Tauri 桌面增强实施计划

## 目标和范围

在 OpenCodex fork 上直接增加桌面能力。保留完整的代理、提供方、模型、子代理、日志、用量、存储和集成等现有功能。Tauri 负责窗口、托盘、应用生命周期和分发；Bun 继续运行原有 TypeScript 后端。

先交付 Windows x64，后续再评估其他系统。GPT / Claude / 其他平台的客户端、账户和联网服务仍属于各功能原有的使用条件；“独立安装”指应用自带 OpenCodex 程序及其运行时。

## 已确定的技术选择

1. 一个 fork 仓库，桌面新增代码集中在 `desktop/`，无需严格禁止修改 `src/`、`gui/` 或现有构建脚本。
2. 原有仪表板由随应用运行的本地后端提供，桌面窗口加载该后端页面。启动中和启动失败时使用轻量的本地提示页面。
3. 安装包携带匹配版本的 Bun、后端代码、生产依赖、原有页面构建产物和必要资源。先保留完整运行目录；是否压缩为单文件，等功能验证后决定。
4. 桌面应用使用自己的数据目录和进程记录。测试额外隔离 Codex / Claude 等目标配置目录。
5. 使用原有 HTTP 接口处理业务操作，只有窗口、托盘及宿主生命周期等能力进入 Tauri 层。
6. 桌面壳和后端一起构建、安装和升级。桌面模式中的 OpenCodex 自更新入口需要适配为整个桌面应用的更新，避免修改全局 npm 安装或只更新一半程序。

## M1：独立窗口与内置后端（开发预览已完成）

- 增加最小 Tauri 工程和开发命令。
- 从项目内的指定 Bun 和源码启动子进程，禁止回退到全局 `ocx` 或已有代理。
- 先在隔离配置下验证：启动子进程、发现实际端口、等待就绪、在窗口中加载原有仪表板。
- 处理启动超时、端口占用、后端退出和可查看的启动日志。
- 用明确的子进程身份识别自身实例；不能把任意 `/healthz` 响应当作自己启动成功。
- 核实 Tauri 本地页面与后端页面的来源边界，原有 OAuth 外链交给系统浏览器；宿主命令只开放必要能力。

验收：从本项目启动窗口并显示本项目后端页面，停止现有全局 OpenCodex 不是这一验证的前置条件。

本阶段已通过项目后端启动/退出测试和实际 Tauri / WebView2 页面加载检查，详见 [M1 验证记录](030_m1.md)。目前使用源码目录中的完整后端；正式资源打包仍在 M3。

## M2：窗口、托盘与生命周期（独立配置部分已完成）

- 单实例启动；再次打开应用时唤起已有窗口。
- 关闭窗口后驻留托盘，托盘提供打开窗口、代理状态和明确的退出操作。
- 区分“隐藏窗口”“停止代理”和“退出应用”；停止和退出沿用上游配置恢复、排空请求的语义。
- 子进程异常退出后展示状态，并提供有界的恢复或重试操作。
- 对开机启动、后台服务和原有 OpenCodex 托盘进行协调，避免两套机制反复拉起进程。
- 正式接管真实 Codex 配置前处理既有全局代理：用户能明确选择切换，不静默抢占路由或停止不属于本应用的进程。

验收：关闭窗口仍可使用代理；明确退出后自身进程可正确结束，配置按既定策略恢复；重复启动和端口冲突行为可预测。

独立配置下的托盘、单实例、启动/停止/重启、崩溃后手动恢复及退出清理已验证，见 [M2 验证记录](040_m2.md)。M2 验收使用隔离预览；固定数据目录、配置导入和真实客户端连接已在后续 M3 中接入，预览模式继续保持隔离。

## M3：完整功能适配与安装包

持久化配置、首次明确连接、配置文件导入和异常恢复已接入；验证记录见 [M3 配置与连接](050_m3_configuration.md)。桌面系统入口适配和 Windows 安装包构建已实现，安装/重装/默认卸载与内置资源验证通过，见 [M3 分发记录](060_m3_distribution.md)。默认全量回归、干净 Windows 与完整手工验收仍未通过，M3 保持开放。

- 保留原有管理页面和后端功能，不以删去页面作为适配方案。
- 检查 OAuth 浏览器打开与回调、文件导入导出、下载、日志目录打开、外链及系统集成。
- 在生命周期验证通过后接入持久化正式配置与已有安装切换；用户明确切换后才接管真实 Codex，开发预览继续独立配置。
- 调整与桌面生命周期重叠的启动、停止、重启、服务、托盘和更新入口；每项保留或调整都记录理由。
- 根据 `package.json`、启动器及资源查找方式确定完整打包清单，包含原生依赖及上游许可证。
- 生成 Windows 安装包，处理 WebView2 前置条件、可写数据目录、升级数据保留和卸载策略。
- 第一版允许手动安装新版本；自动更新如实现，应交付签名校验和整包版本配套机制。

验收：在未安装 OpenCodex、Node.js、Bun 的 Windows 环境安装后可运行；所需系统组件由安装流程检测或提供。

## 验证方法

| 范围 | 验证内容 |
| --- | --- |
| 源码基线 | 上游类型检查、GUI 构建、CLI 入口 |
| 进程与配置 | 单实例、冲突、启动失败、崩溃、退出恢复、现有安装共存 |
| 主要业务 | 提供方、模型、子代理、真实请求、流式响应、日志和用量 |
| 桌面交互 | OAuth、导入导出、下载、外链、窗口和托盘 |
| 分发 | 干净机器安装、升级、卸载，内置运行时来源确认 |

按改动运行相关上游测试和桌面生命周期测试。源码构建通过不能替代真实 API、OAuth 和干净机器验收；需要账户或特定服务的项目应明确记录未验范围。

## 上游同步

保留 `upstream` 作为官方来源，以选定正式版本合并更新到桌面分支。升级后同时构建桌面壳和后端，重复与改动相关的验证。维持 `desktop/` 的职责边界即可，不为未来合并提前重构上游架构。
