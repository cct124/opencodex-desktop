# M3：持久化配置与 Codex 连接

日期：2026-09-11。范围：Windows 源码版桌面应用；安装包仍未交付。

## 实现

- 默认 exe 使用 Tauri 的固定应用数据目录，运行日志与配置分开；`desktop/dev.ps1` 使用 `--preview`。
- 首次进入真实 Codex 前由本地控制页确认目标目录。托盘首次接回先显示控制页。后端重启后，原生恢复和接回维持同一代理进程。
- 上游原生恢复日志仍负责恢复文件；桌面连接记录只记录用户选择及 PID/端口。启动前检查旧进程已退出、当前路由与记录匹配；其他安装的路由与恢复日志不自动接管。
- 退出保留用户连接偏好，下次启动可重新连接；恢复原生和明确停止取消自动连接。
- 配置 JSON 导入先校验、备份，再保存并重启。源文件不变；导入不接管服务、PID、账户库或 OAuth 凭据。无效输入保留原配置。
- 管理页面继续由桌面控制进程和集成切换；首次接入前使用独立 Codex 目录。正式接入后仍关闭自动系统环境注入与历史迁移。
- 真实账号的原生 WS 请求曾出现 1011 关闭，而同一账号/模型的官方 HTTPS 请求成功。因此桌面模式在发送前选用原生 HTTPS/SSE；没有在失败流之后重发请求，普通 CLI 的 WS 行为保持不变。

## 复现

桌面目录：

```powershell
& ..\node_modules\bun\bin\bun.exe run scripts/persistent-smoke.ts
& ..\node_modules\bun\bin\bun.exe run scripts/persistent-window-smoke.ts
```

仅在用户授权真实账号请求后运行：

```powershell
& ..\node_modules\bun\bin\bun.exe run scripts/native-account-smoke.ts --allow-native-request
```

测试目录和日志位于 gitignored 的 `.tmp/desktop/`。测试输出不包含凭据或账号标识。
